## Dependency and runtime analysis

The upstream verification path imports `@noble/curves/ed25519` and `@noble/hashes/sha3`, uses `BigInt`, `Uint8Array`, and `TextEncoder`, and does not require browser globals, wallet bridge, WASM, or secrets. The isolated implementation retains only base58 decoding, hex conversion, hashing/scalar arithmetic, signature verification, and address spend-key extraction. It uses Node-compatible web-standard primitives and imports pinned MIT dependencies.

## Adaptations

- Omitted signing code because server verification does not need secret keys or secure randomness.
- Omitted wallet UI/bridge and address re-encoding helpers.
- Exposed `verifySigV1({ address, message, signature })` that decodes spend key from the address and verifies the exact UTF-8 message bytes.
- Kept the upstream identity/torsion-free key rejection and scalar checks.
- Added a small malformed varint bound guard in address parsing; this is a defensive parsing deviation and must remain covered by tests.
- The parser/policy layer is Sigil-specific and separate from cryptography.

## Fixtures and tests

`tests/sigv1.test.ts` uses the upstream wallet repository's documented `beldex-wallet-cli` signature fixture, address, message, and derived spend key from `test/sign-message.test.mjs`. It also tests message tampering, address checksum, malformed signature, and invalid signature/key lengths. The focused upstream tests `sign-message.test.mjs` and `weak-key-verify.test.mjs` ran at the inspected commit; all 15 passed.

## Current validation status

This verifies execution in Node through Vitest against the upstream CLI fixture. It is not an independently re-run `beldex-wallet-cli verify_value` invocation. ## Known limitation

The upstream test fixture is a CLI-produced SigV1 message signature, not a wallet `beldex-auth-v1` proof generated by an installed extension on testnet. It validates signature format compatibility, not the browser-to-wallet-to-server flow. Deterministic server integration tests use test-only signing material; crypto fixture tests call the real port.
